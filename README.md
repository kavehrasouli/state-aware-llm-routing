# State-aware LLM routing on a heterogeneous CPU-only cluster: artifact

Code and data for a controlled comparison of state-aware routing (lowest resident
KV-cache context per capacity weight) against weighted least-connections (WLC) and
weighted round-robin (WRR), on three Raspberry Pi nodes running llama.cpp.

## Setup

- Nodes: one Raspberry Pi 5 (8 GB) and two Raspberry Pi 4B (4 GB and 8 GB), with fan cooling.
- Engine: llama.cpp build 9960 (`a935fbffe`), `--ctx-size 4096 -np 4 --no-kv-unified --metrics`
  (four 1,024-token slots per node).
- Model: Qwen2.5-0.5B-Instruct, Q4_K_M.
- Router capacity weights: 3.1 : 1.0 : 1.0 (Pi 5 : Pi 4B : Pi 4B).

## Contents

| Folder | Contents |
|---|---|
| `routers/router/` | Router (Rust): routing policies, state poller, router-tracked load, configs (`router_3nodes*.toml`) |
| `benchmarks/` | Benchmark client (`bench.py`), datasets, cost-model sweeps (`cost_model_results_*`, October rerun in `cost_model_rerun_2026-10/`) and fitting scripts |
| `weights_results/` | Capacity calibration runs (two per node) and `compute_weights.py` |
| `3e_results/<policy>/` | Main experiment: one folder per run with `run_meta.json`, the client result JSON, and `router_log.jsonl` |
| `3e_results/analysis/` | Main-experiment analysis scripts, result CSVs, and automated checks |
| `3e_results/freshness_extension_v1/` | Router-tracked load experiment (48 runs; pre-registered `analysis_plan.txt`) |
| `3e_results/model_kv_extension_v1/` | Follow-up: LFM2-350M, OpenELM-450M, and a unified KV pool (84 runs) |
| `simulator/` | Discrete-event cluster simulator and its validation against the hardware runs |
| `figures/results/` | Paper and report figures: results overview, ShareGPT trade-off, routing share |
| `figures/cost_model/` | Cost-model figures |
| `figures/analysis/` | Further analysis figures (generated by `reproduce.py`) |

`3e_results/analysis/run_inclusion.csv` lists every run and whether it passed the validity
filter. One early pilot run is stored but not analyzed (509 run folders, 508 analyzed).

## Reproducing the results (no cluster needed)

Requirements: Python 3.11+, `pip install -r 3e_results/analysis/requirements.txt`, and
Node.js (used by one sensitivity step).

```bash
python -B 3e_results/analysis/reproduce.py            # main experiment: all outputs, figures, 38 checks
python -B 3e_results/analyze_freshness_extension.py   # router-tracked load experiment
python -B 3e_results/analyze_model_kv_extension.py    # follow-up models and KV allocation
python weights_results/compute_weights.py              # capacity weights
```

`reproduce.py` first verifies the hash of every input file; `3e_results/analysis/validate.py`
reruns only the checks.

Cost models (run from `benchmarks/`):

```bash
python analyze_cost_model_sweep.py cost_model_results_pi-node-2_4B-4g/sweep_cost_model_summary.csv
python analyze_cost_model_additive.py
python fit_pi5_candidates.py cost_model_results_pi-node-1_Pi5-8GB/sweep_cost_model_summary.csv
```

Figures: run any `plot_*.py` script from its folder under `figures/`.

Simulator: `python simulator/validate.py`. Router: `cd routers/router && cargo test`.

## Running new experiments

The drivers (`3e_results/run_3e.py`, `run_freshness_extension.py`, `run_model_kv_extension.py`)
only print their plan unless called with `--run`, which requires the cluster. SSH credentials
are not included.
